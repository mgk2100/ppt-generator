# Claude vs Codex — 사진 분석 · 삽화 생성 비교 (2026-09-03)

같은 입력(첨부 Physical AI 슬라이드 JPEG)과 같은 지시문으로 두 도구를 돌렸다.
- Claude = 이 세션(Claude Fable 5.1, Claude Code). 사진 분석은 모델이 직접 보고 씀. 삽화는 **SVG 코드를 작성해 벡터로 그림**(이미지 생성 모델 없음).
- Codex = `codex exec` (gpt-5.6-sol, reasoning high). 사진 분석은 `-i` 로 이미지 첨부. 삽화는 Codex 내장 `imagegen` 스킬(이미지 생성 모델)로 생성.

## 1. 사진 분석 (첨부 슬라이드 구조·디자인 판독)

| 항목 | Claude (`analysis_claude.md`) | Codex (`analysis_codex.md`) |
|---|---|---|
| 6단계 제목·설명문 원문 | 6개 모두 원문대로 옮김 | 5개 옮김. **3단계 설명문을 "보이지 않음"으로 누락**(실제 존재) |
| 박스 안 미세 라벨 | 토큰 3색(보라·초록·주황), 텍스트 지시문 원문("작업 지시: 부품을 잡아 지정 위치에 놓아라")까지 판독 | 상위 라벨 위주. 미세 문구는 "판독 어려움"으로 명시하고 생략 |
| Skill library 카드명 | 적재·본딩·Pick & Place·볼팅·조립 (정확) | "**분동** RFM" 오독(실제 "본딩") |
| 1단계 내부 화살표 | 세 요소 사이 모두 화살표로 기술(부정확 — 실제는 2번째 사진→DB 사이에만 있음) | "두 번째 이미지에서 DB 쪽으로만 화살표" (정확) |
| 6→1 순환선 경로 | 우측 여백→위→1행 중간 높이를 가로질러 좌측→1번 박스 진입 | 우측 바깥→위→"두 행 사이"를 가로질러 좌측→1번 진입 (경로 높이 오판) |
| 3→4 연결 없음 | 지적 | 지적 + 전환본에서 브리지 라벨 추가 제안 |
| 편집 핸들 흔적 | 지적 | 지적 |
| 색상 hex | 원본 편집 파일과 거의 일치 — **단, 이 세션은 분석 전에 원본 PPT XML 을 열어본 적이 있어 순수 이미지 판독으로 볼 수 없음**(공정성 한계) | 이미지만 보고 추정. 계열은 맞고 값은 ±10~20 오차 |
| 불확실성 표기 | 약함 | 좋음 — 판독 불가·추정을 문두에 명시 |
| 전환안 품질 | 6단계 1:1 대응 + 하단 패널 문구 확정형 | 6단계 1:1 대응 + 시각 요소 치환표 + "Strategy library" 명칭 제안. 요소 3의 DB 항목이 더 풍부(질의·산출물·검증 결과·피드백) |
| 소요 시간 | 즉시(대화 내) | 약 4분 |

**판정 — 사진 분석은 Claude 우세, 근소.** 작은 글자 판독(설명문·카드명)에서 Codex 가 2건 틀렸고 Claude 는 화살표 위치 1건 틀렸다. 구조·전환안의 짜임새는 둘 다 실무에 바로 쓸 수준이며, 불확실성을 밝히는 태도는 Codex 가 낫다.

## 2. 삽화 생성 (박스 안 아이콘 17종)

(아래 표는 Codex 생성 완료 후 채움)

| 항목 | Claude (SVG 코드) | Codex (imagegen 이미지 생성) |
|---|---|---|
| 생성 방식 | 17종을 한 스크립트(`make_icons.py`)로 작성 → rsvg-convert 로 PNG. 벡터라 크기 무관, PowerPoint 에서 재편집 가능 | 내장 imagegen 모델로 1장씩 생성 후 `out/` 로 복사. 래스터(1254px) |
| 소요 시간 | 코드 작성 1회 + 렌더 5초. 추가 2종도 즉시 | 15종 약 19분(장당 1~1.5분) + 추가 2종 3분. 이후 자가 점검으로 01·02 재생성 시도 |
| 참고 슬라이드 톤 재현 | 팔레트·선 굵기·신경망 모양이 원본과 거의 같음(가벼운 선화) | 사물 삽화(서버 랙·문서·방패·말풍선)는 원본보다 풍부하고 완성도 높음. 신경망 3종은 **검은 면이 깔린 무거운 그림**으로 원본 톤과 어긋남 |
| 일관성 | 17종 선 굵기·색 완전 동일 | 종마다 선 굵기·밀도 편차(01 얇음 ↔ 06·08·11 무거움) |
| 투명 배경 | 전부 투명 | 17종 중 13종 투명. **01·02 는 체커보드 무늬가 픽셀로 박혀 나옴** → 후처리(`postprocess.py`) 필요. Codex 도 마지막에 스스로 발견해 수정 착수 |
| 지시 준수 | 글자 없음, 색 제한 준수 | 글자 없음 준수. 02 에 `</>` 넣고 나서 "잘못 들어갔다"고 스스로 삭제 시도(지시상 허용 항목이었음) |
| 약점 | 표현력 단순 — 엄지(09)·압축 화살표(10)가 어색 | 비결정적(다시 돌리면 다른 그림), 편집 불가, 후처리 필수 |
| 슬라이드 적용 결과 | `output/sw-dev-ai-llm-claude-icons.pptx` — 정갈하지만 밋밋 | `output/sw-dev-ai-llm-codex-icons.pptx` — 풍부하지만 신경망이 검게 뭉침 |

**판정 — 삽화 생성은 Codex 우세(표현력·완성도), 통제·일관성은 Claude 우세.**
최종 채택 = **혼합판** `output/sw-dev-ai-llm.pptx`: 신경망·압축·대화(01·06·07·08·10) = Claude, 사물 삽화 12종 = Codex. 원본 Physical AI 의 가벼운 신경망 톤을 유지하면서 사물은 풍부하게.

## 3. 한 줄 결론
- **사진 분석**: Claude 근소 우세(작은 글자 판독 정확도). Codex 는 불확실성 표기와 전환안 제안이 좋음.
- **사진 생성**: Codex 우세 — 이미지 생성 모델을 내장해 "그림"을 만들 수 있고 품질도 높다. Claude 는 이미지 생성 모델이 없어 코드로 벡터를 그리며, 일관성·편집성·속도에서 앞선다.
- 실무 권장: 아이콘·삽화가 필요하면 Codex imagegen 으로 뽑고 Claude 가 후처리·배치·일관성 검수. 도식 전체 레이아웃(PPT 코드)은 Claude.
