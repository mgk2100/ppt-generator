## A. 데이터 취득·자산화 (가장 많이 물을 부분)

**Q1. 데이터는 지금 얼마나 확보돼 있나?**
- 사내 코드: 약 25만 조각(247,487 chunks, 8,040만 자 ≈ 2,000만~2,700만 토큰) — 코드 검색용 DB에 적재 완료. (coding-assistant `docs/specs/2026-07-18-spec3-domain-draft-training-design.md`)
- 설계자 질의·답변: 97턴, 25KB 수준(2026-07-18 시점) — 사실상 아직 없다. 플랫폼이 설계자에게 열리는 2027년 1월 이후 본격 축적.
- 답변 요령: "코드 자산은 확보됐고, 부족한 것은 설계자의 질의·답변 데이터다. 그래서 상용 LLM 을 쓰는 동안 그 대화를 자동으로 쌓는 장치를 먼저 만들었다."

**Q2. 데이터 취득은 어떻게 늘리나? (우리 역량이 부족한 부분)**
- 자동 기록: 설계자가 상용 LLM(Claude·Codex)에 질문하면 질문·시스템 입력·답변·사용량이 기록된다(`tb_llm_trace`, 2026-07-28 설계, 기본 off 스위치). 채택/불채택 평가(`tb_feedback` 엄지 위·아래 + 사유), 복사·재시도·편집 같은 행동 신호(`tb_turn_signal`)도 함께 기록.
- 플러그인 대화도 적재: Claude Code 플러그인(sl-sw-agent)에서 오간 설계자 대화 원문이 `tb_llm_wiki_log` 에 쌓인다.
- 지식 유닛 추출 파이프라인 구현 완료: 쌓인 대화를 사내 LLM 이 읽어 질답·결정·패턴·방법·주의점·참조·기타 7종 지식 단위로 뽑고, 신뢰도 0.6 미만 제거·개인정보 삭제·중복 제거 후 검색 DB에 넣는다(`mcp_server/infrastructure/knowledge/distill/distill.py`, 1,432줄).
- 업로드 자산: 코드 zip → MinIO 원본 보관 + 검색용 조각(pgvector) + 구조 파일(심볼·호출 관계·모듈 요약, vault). 설계 문서 생성기의 파싱 결과·생성 문서·섹션 편집 이력(승인자 포함)도 저장.
- 학습용 추출 스크립트(`agent/scripts/export_llm_traces.py`)가 기록·평가·행동 신호를 합쳐 학습 입력 형식(JSONL)으로 뽑는다. 교사 = 상용 모델 출력(2026-07-28 확정).
- 답변 요령: "설계자가 별도 작업 없이 평소처럼 AI 를 쓰면 데이터가 쌓이도록 만들었다. 지금은 스위치를 켜고 사용자 수를 늘리는 단계다."

**Q3. 정제는 무엇을 하나?**
- 중복 제거, 사내 보안 규칙(SWA-14) 기준 민감 문자열 삭제, 길이 필터(200~32,000자), 개인정보 삭제, 지식 유닛 신뢰도 게이트. 컴파일 통과 코드만 학습 쌍으로 채택(정적 검증 수정안의 경우).
- 사내 코드를 외부 학습 서비스로 보내는 경로는 기본 차단(`sllm/preprocess/egress_guard.py`, 명시적 opt-in 필요).

**Q6. 최상위 모델을 사내 서버에 올리면 안 되나?**

- 보유 GPU 는 NVLink(카드 간 고속 연결) 미지원 → 4장 넘게 묶으면 통신 병목. 이 등급은 H200/B200 데이터센터급 장비 영역.
- 실험 근거: 754B급 GLM-5.2 를 1bit 극압축(217GB)으로 올려 봤더니 4.9 tok/s(1명도 곤란)·코딩 벤치 88.75%(채택 32B 95% 대비 열세) → 불채택.

## C. 학습·성능

**Q7. 학습에 얼마나 걸리나?**
- 실측(소형 보조 모델, 2026-07-20): 사내 코드 3.5만 건 대화 형식, 4회 반복 학습, 7,099초(≈2시간), GPU 1장 최대 메모리 52GB. 1,000건 예비 실험은 267초.
- **추정**: 30B급(Qwen3-Coder-30B-A3B, LoRA) 사내 특화 학습 — 2,000만 토큰 × 3회 반복을 GPU 1장에서 돌리면 하루 안팎. 아직 완료된 학습 이력은 없고, 설정과 1회 완주 점검만 존재.
- 답변 요령: "학습 시간은 하루 단위라 문제가 아니다. 문제는 학습시킬 데이터가 아직 적다는 것이다."

**Q8. 사내 LLM 이 상용 수준이 되나?**
- 15종 이상 실서버 실측(2026-06~07): 96GB GPU 1~2장으로는 30B급이 현실적 상한. 대형 모델은 4bit 압축 품질 손실로 중형보다 낫지 않았고 일부는 답을 정리하지 못함.
- 채택 모델 Gemma-4-31B(4bit) = p50 172 tok/s, 32명 동시 요청에도 121 tok/s. 현재 용도 = 코드 분석 서술·모듈 요약·검색 임베딩(Qwen3-Embedding-8B).
- 동시 처리(GPU 1장): 짧은 질의응답 30명 이상 / 중간 문서 약 2명 / 긴 문서 약 1명. GPU 4장이면 약 4배.
- 전략(2026-07-28 승인): 현재 상용 중심 → 2027-01부터 축적 데이터로 지식증류 학습 → 기능별 상용·사내 병행. 코드 생성은 상용 유지, 문서·분석부터 병행.

**Q9. 사내 LLM 학습이 이미 시도됐나? 결과는?**
- 보조(초안) 모델 사내 데이터 학습 2회: 첫 학습 τ 1.42, 자기 생성 데이터 재학습 후 1.57 — 범용 초안 모델(2.79)에 못 미쳐 불채택. 원인 = 학습 데이터(코드 조각)와 실제 사용 분포 불일치. → 설계자 실사용 데이터 확보가 선결 과제라는 근거.

## D. 보안·일정·효과

**Q10. 사내 코드가 외부로 나가지 않나?**
- 사내 코드의 외부 학습 서비스 송신은 기본 차단(보안 게이트). 상용 LLM 은 기업용 계약 경로(Enterprise API·구독)로만 사용. 사내 LLM 학습·추론은 사내 서버 내.
- 미결: 상용 LLM 답변을 학습에 쓰는 것은 약관 회색지대 → 법무 확인 병행 권고(2026-07-28 설계 문서). 구두 대비: 상용 전환 후 보안 대책, 상용 운영 비용 규모.

**Q11. 일정은?**
- 2026.08 코딩 지원 상용 LLM 1차 전환 → 09 사용 이력 축적 시작 → 11 1차 지식증류 학습·검증 → 12 테스터 기반 1차 통합 구축 → 2027.01 중순 SW 설계자 오픈 → 2027.01부터 사내 LLM 학습 본격화.

**Q12. 기대 효과는?**
- 설계 문서(SAD·SDD) 작성 공수 80% 이상 절감 목표(계획서). 실측: 컴포넌트 1개 SAD 약 50분 자동 생성, SAD+SDD 재생성 60분 이내.
- 정적 검증: 2,040개 파일 35분 24초 완주, MISRA 규칙 131개 자동 검사(cppcheck 애드온), 121개 작업에서 25.6만 건 지적 처리 실측.
- 신규 인력 숙련 시간 단축, 개발 문서 표준화(계획서 목표).

## F. 용어 (임원 질문 대비)
- LLM(Large Language Model): 대규모 언어 모델. 토큰: AI 가 글을 처리하는 최소 단위(한글 약 1~2자). 30B: 매개변수 300억 개 규모.
- 지식증류: 고성능 AI(교사)의 답변으로 소형 AI(학생)를 학습시켜 성능을 근접시키는 기법. 양자화: 가중치 정밀도를 낮춰 모델을 1/4 등으로 압축(품질 손실 동반).
- SAD(Software Architecture Design Specification)·SDD(Software Detailed Design Specification): SW 아키텍처·상세 설계 문서. MISRA(Motor Industry Software Reliability Association): 차량용 C 코딩 규칙. NVLink: GPU 간 고속 직결 연결. vLLM: 사내 서버에서 LLM 을 서비스하는 소프트웨어.
