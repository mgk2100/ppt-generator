# 첨부 슬라이드 분석 (Claude)

> 분석 기준: 첨부 이미지(제조 Physical AI, 1306×744 JPEG)를 보고 판독. 원본 편집 파일은 참조하지 않음. 미세 문구는 판독 가능한 범위에서 원문 그대로 옮김.

## 1. 구조

### 1.1 전체 구성
- 좌상단 파란 세로 태그 `RFM`, 제목 `제조 Physical AI`, 우상단 `SL` 로고, 제목 아래 가는 구분선.
- 부제: `현장 데이터 수집부터 Skill library 까지, 6단계로 이어지는 RFM 개발 파이프라인` — 뒷부분(`6단계로 이어지는 RFM 개발 파이프라인`)만 파랑.
- 본문 = 3열 × 2행 6개 박스(둥근 모서리, 흰 배경, 연파랑 테두리). 각 박스 = 남색 번호 원 + 굵은 단계 제목 / 연파랑 점선의 안쪽 패널(연회청 배경) / 하단 한 줄 설명문.
- 하단 = 좌측 현장 사진, 중앙 굽은 화살표(문구 포함), 우측 `Skill library` 패널.

### 1.2 단계별 내용
| # | 제목 | 설명문(원문) | 박스 안 요소(좌→우) |
|---|---|---|---|
| 1 | 데이터 취득·자산화 | 로봇이 수행할 공정을 사람이 직접 지도해 데이터를 얻는 과정 | 작업자가 로봇팔을 손으로 지도하는 사진 → 작업대 위 상자 사진 → 회색 DB 실린더 `데이터 자산화`(아래 `이미지, 명령어, 관절각`) |
| 2 | 시연 데이터 토큰화 | 다른 형태의 언어를 AI모델이 이해할 수 있는 언어로 번역하는 단계 | 세 줄 입력(`비전` 이미지 프레임, `텍스트` "작업 지시: 부품을 잡아 지정 위치에 놓아라", `액션` 파형) → `비전 토큰`(보라 블록)·`텍스트 토큰`(초록)·`액션 토큰`(주황) → 색 큐브를 쌓은 `통합토큰` |
| 3 | 시연 데이터 학습 | 시연 데이터를 범용 RFM에 기본 동작 능력을 빠르게 확보한 RFM | 로봇 작업 이미지 묶음 `시연 데이터` → 보라 신경망 `범용 RFM` → 초록 신경망 `도메인 적응 RFM` (박스 우상단에 작은 사진 썸네일) |
| 4 | 강화학습 | 가상환경에서 반복 시행착오를 거쳐 여러 예외 상황에도 안정적인 RFM | 시뮬레이션 장면(격자 위 로봇 다수) `시뮬레이션` → 초록 신경망 `도메인 적응 RFM` → 파랑 신경망 `고도화 RFM` |
| 5 | 경량화 | 대형 모델을 저전력 장비에서도 구동 가능하도록 압축된 RFM | 파랑 신경망 `고도화 RFM` → 뇌·물방울·격자 도식 `지식증류 & 양자화` → 작은 파랑 신경망 + 속도계 `경량 RFM` |
| 6 | 추론 제어 | 실시간 추론으로 발생하는 새 데이터를 다시 수집하는 단계 | 소형 컴퓨터 + 신경망 `상위 제어기` → 로봇 작업 사진 `로봇 작동` → 회색 DB 실린더 `추론 데이터 자산화`(아래 `이미지, 명령어, 관절각`) |

- 박스 안 요소 사이 화살표 = 작고 옅은 회청색 오른쪽 화살표(그라데이션).
- 6번 제목 주변에 선택 핸들(조절점)이 찍혀 있음 — 캡처 당시 편집 상태 흔적, 내용 요소 아님.

### 1.3 단계 간 연결
- 1→2, 2→3, 4→5, 5→6: 박스 사이 진한 파랑 `→`.
- 3→4: 직접 연결선 없음(번호 순서로만 이어짐).
- 6→1 순환선: 6번 박스 오른쪽에서 나가 우측 여백을 따라 위로 올라간 뒤, 1행 박스 높이의 중간(제목 아래 라인)에서 왼쪽 끝까지 가로지르고, 좌측 여백에서 아래로 내려와 1번 박스 왼쪽으로 화살표가 들어감. 즉 "추론 데이터 자산화 → 데이터 취득·자산화" 재수집 루프. (선이 1~3번 박스 위를 지나 다소 겹쳐 보임.)

### 1.4 하단 영역
- 좌: 1번과 같은 작업자–로봇 협업 사진.
- 중: 하늘색 굽은 화살표(아래로 내려와 오른쪽으로 꺾임), 문구 `데이터 기반 지속적 모델 고도화로 **도메인 특화 RFM 완성**`(뒷부분 굵게).
- 우: 연파랑 패널 `Skill library`, 우상단 `RFM 플랫폼`. 카드 5개 = `적재 RFM`, `본딩 RFM`, `Pick & Place RFM`, `볼팅 RFM`, `조립 RFM`(주황 신경망 + 속도계). 하단 설명 `여러 특화 RFM을 하나의 플랫폼에 담아 Skill library화 하여 필요한 공정에 따라 사용함.`

- 폰트: 한글 고딕(Noto Sans KR 계열로 보임). 위계 = 제목 ~20pt bold > 부제 ~16pt bold > 단계 제목 ~13.5pt bold > 번호 12pt > 설명문 ~9.5pt > 라벨 9pt bold > 미세 라벨 7pt.
- 격자: 박스 가로:세로 ≈ 2:1, 열 간격 ≈ 박스 폭의 7%, 행 간격은 매우 좁음(≈0.1"). 좌우 여백 ≈ 슬라이드 폭 2.5%. 상단 제목 띠 / 6단계 격자 / 하단 띠의 3층 구조. 하단은 좌(사진+화살표) : 우(패널) ≈ 1 : 1.
- 태그 `RFM`은 슬라이드 위쪽 가장자리에 붙은 세로 탭 형태(윗부분이 잘려 들어감), 로고는 우상단.

## 3. LLM 개발 파이프라인 전환안
| # | 단계 제목 | 설명문 | 요소 1 | 요소 2 | 요소 3 |
|---|---|---|---|---|---|
| 1 | 데이터 취득·자산화 | 설계자의 질의·답변과 문서·코드를 지식 단위로 쌓는 과정 | 설계자 ↔ AI 질의응답 | 문서·코드 업로드 | 데이터 자산화 DB(`질문·답변, 문서, 코드`) |
| 2 | 데이터 정제·구조화 | 중복·오류·민감정보를 걸러내 학습용 데이터로 바꾸는 단계 | 정제·선별(깔때기) | AI 학습 형태로 변환(토큰) | 학습 데이터 |
| 3 | 사내 LLM 학습 | 사내 데이터를 범용 모델에 학습시켜 사내 LLM 을 만드는 단계 | 학습 데이터 | 범용 LLM(보라) | 사내 적응 LLM(초록) |
| 4 | 피드백 고도화 | 설계자의 채택·수정 평가를 재학습해 정확도를 높이는 단계 | 설계자 평가 | 사내 적응 LLM(초록) | 고도화 LLM(파랑) |
| 5 | 경량화·배포 | 압축한 모델을 사내 서버에 올려 다수 설계자가 함께 쓰는 단계 | 고도화 LLM | 지식증류 & 양자화 | 사내 GPU 서버 |
| 6 | 활용·재수집 | 플랫폼에서 답하며 생기는 새 데이터를 다시 자산으로 쌓는 단계 | 통합플랫폼(웹·IDE) | 사내 LLM 답변 | 새 데이터 자산화 DB |

- 하단: 좌측 사진 → SL SW Agent 웹 실화면, 굽은 화살표 → `데이터 기반 지속 학습으로 상용 LLM 의존 축소, SL 특화 LLM 완성`, 우측 패널 → `SW 설계 지원 서비스`(문서 생성 / 코드 생성 / 정적 검증 3카드, 각 카드에 "자산 → 활용" 두 줄), 우상단 `통합플랫폼 (SL SW Agent)`.
- 순환선은 원본처럼 6→1 유지하되 박스 위를 지나지 않도록 부제와 1행 사이 여백으로 우회.
