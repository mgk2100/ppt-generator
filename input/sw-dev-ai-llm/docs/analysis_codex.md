# 첨부 슬라이드 분석

> 분석 기준: 첨부된 래스터 이미지를 육안으로 판독했다. 작은 도식 내부의 미세 문구는 완전한 판독이 어려워, 명확히 보이는 상위 라벨을 중심으로 기록했다. 색상과 글자 크기는 원본 편집 파일이 아닌 이미지에서 추정한 값이다.

## 1. 구조

### 1.1 전체 구성

- 상단 제목: `제조 Physical AI`
- 상단 부제: `현장 데이터 수집부터 Skill library 까지, 6단계로 이어지는 RFM 개발 파이프라인`
- 본문은 **3열 × 2행**, 총 **6단계**의 둥근 모서리 박스로 구성된다.
- 각 단계 박스는 대체로 `번호 원 + 단계 제목`의 헤더, 연한 파랑 점선의 내부 도식 패널, 하단 설명문으로 구성된다.
- 읽기 순서는 번호상 위 행의 1→2→3, 아래 행의 4→5→6이다. 같은 행의 단계 사이는 오른쪽 방향 화살표로 연결된다.

### 1.2 단계별 내용

#### 1단계 — 데이터 취득·자산화

- 하단 설명문: `로봇이 수행할 공정을 사람이 직접 지도해 데이터를 얻는 과정`
- 박스 안 요소, 왼쪽부터:
  1. 작업자가 로봇 팔을 직접 지도하는 현장 사진
  2. 로봇 작업 대상이 보이는 시연 데이터 이미지
  3. 회색 데이터베이스 아이콘과 라벨 `데이터 자산화`; 하단 데이터 종류 `이미지, 명령어, 관절각`
- 두 번째 이미지에서 데이터베이스 쪽으로 흐르는 옅은 회색 오른쪽 화살표가 있다.

#### 2단계 — 시연 데이터 토큰화

- 하단 설명문: `다른 형태의 언어를 AI모델이 이해할 수 있는 언어로 번역하는 단계`
- 박스 안 요소, 왼쪽부터:
  1. 세 입력 양식: `비전` 이미지 프레임 묶음, `텍스트` 작업 지시문, `액션` 시계열 그래프
  2. 입력별 색상 토큰: `비전 토큰`, `텍스트 토큰`, `액션 토큰`
  3. 여러 색의 입방체를 쌓은 `통합토큰` 아이콘
- 각 입력에서 대응 토큰으로, 다시 통합토큰으로 향하는 옅은 회색 오른쪽 화살표가 있다.

#### 3단계 — 시연 데이터 학습

- 하단 설명문: **별도의 설명문이 보이지 않음**
- 박스 안 요소, 왼쪽부터:
  1. 여러 장의 로봇 작업 이미지와 라벨 `시연 데이터`
  2. 자주색 신경망 아이콘과 라벨 `범용 RFM`
  3. 녹색 신경망 아이콘과 라벨 `도메인 적용 RFM`
- 세 요소 사이에 옅은 회색 오른쪽 화살표가 있어 `시연 데이터 → 범용 RFM → 도메인 적용 RFM`의 흐름을 만든다.

#### 4단계 — 강화학습

- 하단 설명문: `가상환경에서 반복 시행착오를 거쳐 여러 예외 상황에도 안정적인 RFM`
- 박스 안 요소, 왼쪽부터:
  1. 로봇 작업 가상환경 이미지와 라벨 `시뮬레이션`
  2. 녹색 신경망 아이콘과 라벨 `도메인 적용 RFM`
  3. 파란색 신경망 아이콘과 라벨 `고도화 RFM`
- 요소 사이에 옅은 회색 오른쪽 화살표가 있다.

#### 5단계 — 경량화

- 하단 설명문: `대형 모델을 저전력 장비에서도 구동 가능하도록 압축된 RFM`
- 박스 안 요소, 왼쪽부터:
  1. 파란색 신경망 아이콘과 라벨 `고도화 RFM`
  2. 증류·양자화 개념도와 라벨 `지식증류 & 양자화`
  3. 축소된 신경망과 속도계 아이콘, 라벨 `경량 RFM`
- 요소 사이에 옅은 회색 오른쪽 화살표가 있다.

#### 6단계 — 추론 제어

- 하단 설명문: `실시간 추론으로 발생하는 새 데이터를 다시 수집하는 단계`
- 박스 안 요소, 왼쪽부터:
  1. 엣지 컴퓨터 이미지와 라벨 `상위 제어기`
  2. 로봇 작업 현장 이미지와 라벨 `로봇 작동`
  3. 회색 데이터베이스 아이콘과 라벨 `추론 데이터 자산화`; 하단 데이터 종류 `이미지, 명령어, 관절각`
- 요소 사이에 옅은 회색 오른쪽 화살표가 있다.
- `추론 제어` 제목 주변에는 크기 조절점, 회전점, 이동 커서가 노출되어 있다. 이는 내용 요소라기보다 편집 중 선택된 텍스트 상자의 흔적으로 보인다.

### 1.3 단계 간 연결

- 1→2, 2→3: 위 행 박스 사이에 진한 파랑의 오른쪽 화살표.
- 4→5, 5→6: 아래 행 박스 사이에 진한 파랑의 오른쪽 화살표.
- 3→4: 번호상 다음 단계이지만, 이미지에는 두 박스를 직접 잇는 명시적인 화살표가 보이지 않는다.
- 6→1 재순환: 6단계 오른쪽에서 나간 진한 파랑 선이 슬라이드 우측 바깥쪽으로 뻗은 뒤 위로 올라가고, 두 행 사이를 가로질러 왼쪽 끝으로 돌아간 다음 다시 위로 올라가 1단계 왼쪽으로 들어간다. 1단계 진입부의 화살촉은 오른쪽을 향한다. 즉 `추론 데이터 자산화 → 데이터 취득·자산화`의 피드백 루프다.

### 1.4 하단 영역

- 왼쪽: 1단계에서 사용한 것과 같은 작업자–로봇 협업 현장 사진.
- 중앙: 아래로 내려왔다가 오른쪽으로 꺾이는 굵은 하늘색 굽은 화살표. 문구는 `데이터 기반 지속적 모델 고도화로 도메인 특화 RFM 완성`.
- 오른쪽: 연한 파랑 배경의 `Skill library` 패널. 우측 상단에는 `RFM 플랫폼`이 표시된다.
- 패널 안 항목, 왼쪽부터:
  1. `적재 RFM`
  2. `분동 RFM`
  3. `Pick & Place RFM`
  4. `볼팅 RFM`
  5. `조립 RFM`
- 각 항목은 주황색 신경망과 작은 속도계 아이콘을 담은 카드 형태다.
- 패널 하단 설명: `여러 특화 RFM을 하나의 플랫폼에 담아 Skill library화 하여 필요한 공정에 따라 사용함.`

### 2.3 격자·비율·여백

- 본문 격자: **2행 × 3열**.
- 각 단계 박스의 가로:세로 비율은 약 **2.0:1**이다.
- 세 열의 폭은 거의 동일하며, 열 사이 간격은 박스 폭의 약 **7%** 정도다.
- 두 행의 박스 높이는 거의 같고, 행 사이 간격은 매우 좁아 박스 높이의 약 **3–4%** 수준이다.
- 슬라이드 좌우 바깥 여백은 전체 폭의 약 **2–2.5%**로 작다.
- 각 박스 내부는 좌우 약 3–4% 패딩을 두고, 제목 아래에 폭 대부분을 차지하는 점선 패널을 배치한다.
- 상단 제목 영역, 6단계 격자, 하단 라이브러리 영역의 세 수평 띠가 명확하다.
- 하단은 왼쪽 사진과 중앙 화살표가 전체 폭의 약 절반, 오른쪽 Skill library 패널이 나머지 절반을 차지한다.

### 2.4 상단 태그와 로고

- `RFM` 태그: 슬라이드 좌측 상단에 붙은 세로형 파란 라운드 사각형. 흰색 `RFM`이 중앙에 있고, 태그 오른쪽에 제목이 배치된다.
- 로고: 슬라이드 우측 상단에 파란색 이탤릭 형태의 `SL` 로고가 있다.
- 제목 영역 아래에는 좌우 여백 안쪽을 가로지르는 얇은 검정 구분선이 있다.

## 3. 「AI 기반 SW 설계 지원 플랫폼의 LLM 개발 파이프라인」 전환안

원본의 시각 문법을 그대로 유지하되, `RFM`을 `설계 특화 LLM`, 로봇 시연 데이터를 `설계자의 질의·답변 및 업로드 자산`, 추론 제어를 `플랫폼 활용`으로 치환하는 방식이다.

| 단계 | 제안 단계 제목 | 제안 설명문 | 박스 안 요소 1 | 박스 안 요소 2 | 박스 안 요소 3 |
|---:|---|---|---|---|---|
| 1 | **설계 지식 수집·자산화** | 설계자의 상용 LLM 질의·답변과 업로드 문서·코드를 지식 유닛으로 DB에 축적하는 단계 | 상용 LLM 질의·답변 화면 | 업로드 문서·소스 코드 묶음 | `지식 유닛 DB` 아이콘 (`질문, 답변, 문서, 코드, 메타데이터`) |
| 2 | **지식 유닛 정제** | 수집한 이종 설계 지식을 학습 가능한 일관된 형식으로 정제·구조화하는 단계 | 원천 지식 유닛 (`대화·문서·코드`) | 정제 파이프라인 (`중복 제거·비식별화·청킹·라벨링`) | `정제 학습셋` 데이터 큐브 |
| 3 | **로컬 LLM 학습** | 정제된 설계 지식으로 기본 로컬 LLM을 학습해 도메인 설계 역량을 확보하는 단계 | `정제 학습셋` 카드 묶음 | `기본 로컬 LLM` 신경망 | `설계 특화 LLM` 신경망 |
| 4 | **피드백 고도화** | 설계자 평가와 검증 결과를 반복 반영해 다양한 설계 상황에서 답변 품질을 높이는 단계 | `설계자 피드백·평가 결과` 대시보드 | `설계 특화 LLM` 신경망 | `고도화 LLM` 신경망 |
| 5 | **경량화** | 고도화 모델을 사내·로컬 환경에서도 효율적으로 구동하도록 압축하는 단계 | `고도화 LLM` 신경망 | `지식증류 & 양자화` 개념도 | `경량 로컬 LLM`과 속도계 아이콘 |
| 6 | **플랫폼 활용·재수집** | 플랫폼 활용 중 발생한 질의·산출물·평가 데이터를 다시 지식 유닛으로 자산화하는 단계 | `AI 기반 SW 설계 지원 플랫폼` 화면 | `문서 생성·코드 생성·정적 검증` 활용 장면 | `활용 데이터 자산화` DB (`질의, 산출물, 검증 결과, 피드백`) |

### 3.1 단계 간 흐름 적용

- 상단: `1 설계 지식 수집·자산화 → 2 지식 유닛 정제 → 3 로컬 LLM 학습`
- 하단: `4 피드백 고도화 → 5 경량화 → 6 플랫폼 활용·재수집`
- 재순환선: `6 활용 데이터 자산화 → 1 설계 지식 수집·자산화`
- 원본에서 시각적으로 빠져 있는 3→4 연결은 전환본에서는 명시하는 편이 좋다. 우측에서 아래 행 좌측으로 돌아가는 꺾은선 또는 `학습 모델 배포·평가`라는 짧은 브리지 라벨을 넣으면 6→1 피드백선과 혼동을 줄일 수 있다.

### 3.2 하단 라이브러리 전환안

- 왼쪽 사진: 작업자–로봇 사진을 **설계자가 플랫폼에서 요구사항·아키텍처·코드를 검토하는 화면**으로 교체.
- 굽은 화살표 문구: `설계 지식 기반 지속적 모델 고도화로 도메인 특화 LLM 완성`.
- 패널 제목: `Strategy library` 또는 원본 명칭을 유지한 `Skill library`.
- 패널 우측 상단: `AI 기반 SW 설계 지원 플랫폼`.
- 패널 카드 3개, 왼쪽부터:
  1. `문서 생성` — 요구사항서, 설계서, API 명세서 아이콘
  2. `코드 생성` — 소스 코드, 테스트 코드, 리팩터링 아이콘
  3. `정적 검증` — 규칙 검사, 보안 취약점, 품질 리포트 아이콘
- 패널 하단 설명 제안: `설계 특화 LLM의 세 가지 지원 전략을 하나의 플랫폼에 담아 개발 단계와 목적에 따라 활용함.`
