# ai-pipeline-6steps — LLM · Vision · 로봇 공통 6단계 (총괄센터장 보고용)

## 왜 만들었나
총괄센터장님 질의 = "AI 를 쓰는 일이니 Vision · 로봇도 같은 조직에서 할 수 있지 않나".
세 분야를 **같은 6단계 위에 올려놓고** 각 단계에서 하는 일이 어떻게 다른지 보이는 것이 이 자료의 목적이다.

**결론 = 6단계 전부 수행 방식이 달라 LLM · Vision · 로봇은 별도로 운영 · 개발되어야 한다 (2026-09-18 사용자 확정).**
특정 단계를 강조하지 않는다 — 한 단계만 부각하면 "나머지는 같다" 로 읽힌다.
본 덱의 6개 박스는 테두리 · 색 · 크기가 모두 같고, 제목 아래 한 줄이 결론을 그대로 적는다.

## 산출물
| 파일 | 내용 |

| `output/ai-pipeline-6steps-1.pptx` ~ `-6.pptx` | **첨부 6장** — 단계마다 1장. SW Agent(LLM) · 영상 · LiDAR 인지(Vision) · 로봇 3열, 각 열 = **큰 그림 1장 + 설명 한 블록**(작업 내용 — 어려운 점). **세 열을 나란히 읽는 것이 곧 그 단계의 분야별 차이 정리**이므로 하단 결론 밴드 · 각주를 두지 않는다 |

## 6단계 기준 (2026-09-18 확정)
근거 = `LLM 파트 프로세스 정리.pptx`(6단계) + `비전 파트 프로세스 정리.pptx`(6단계)를 대조해
**어느 한쪽 파트에 기울지 않는 AI 개발 생애주기**로 공통 축을 잡았다.

| # | 제목 | 부제 | 이 단계에서 갈리는 것 |
|---|---|---|---|
| 1 | 데이터 취득 | 현장 · 사내에서 실제 활용에 필요한 데이터 수집 | 사내 코드 · 규칙 · 질의 답변(LLM) / 촬영 계획 · 장비 · 인력 선행(Vision) |
| 2 | 데이터 가공 | 수집 데이터를 활용 가능한 형태로 변환 | 조각으로 분할(LLM) / 사람이 한 장씩 레이블링(Vision) |
| 3 | AI 모델 확보 | 상용 모델 도입 또는 자체 모델 개발 | LLM 은 모델 제작 없음 / Vision · 로봇은 직접 학습 |
| 4 | 서빙 환경 구성 | 서버 · 현장 환경 구축 | 서버에서 데이터 결합(LLM) / 경량화 후 장비 탑재(Vision) |
| 5 | 성능 평가 · 개선 | 결과 측정 후 미달 항목 보완 | 데이터 품질 개선(LLM) / 모델 구조 · 학습 반복(Vision) |
| 6 | 배포 · 운영 | 실사용 적용 및 운영 데이터 재수집 | 산출물 재수집(LLM) / 장비 배포 후 추론(Vision) |

- 제목 · 부제 모두 **명사형 보고서체**로 쓴다. 질문형 구어체("무엇을 재료로 쓰는가")는 쓰지 않는다
  (2026-09-18 사용자 지시). 제목은 기술 용어를 그대로 쓰고, 부제가 그 단계에서 하는 일을 한 줄로 적는다.
- **쓰지 않는 말 (2026-09-18 사용자 지시)** — 자세한 이유는 `steps.py` 머리말에 있다.
  - **"공통"** : 본 덱 제목을 「공통으로 적용되는 6단계」 → 「LLM · Vision · 로봇 파이프라인 6단계」로 바꿨다.
    "공통"이라고 적으면 한 분야 인력이 다른 분야도 할 수 있다는 뜻으로 읽힌다.
  - **"자동"** : 데이터가 사람 손 없이 쌓인다는 뜻으로 읽힌다. "데이터로 수집" 으로 적는다.
  - **설명문 · 안내문** : 「~ 첨부를 열어 비교한다」 같은 사용 안내, 「그림은 미확정」 같은 각주를 넣지 않는다.
- **작업 내용만 적지 않는다.** 무엇이 어려운지를 `—` 뒤에 함께 적어야 분야가 다르다는 것이 전달된다.
  그림을 키운 뒤로는 수행 주체 줄을 빼고 한 블록으로 합쳤다(2026-09-18).
- **수치는 계산을 맞추고 근거를 적는다.** 레이블링 비용은 박스 레이블 1장당 50~100원,
  현장 서비스화 수준 10만~50만 장 기준 **500만~5,000만 원**(업계 통상)으로 적는다.
  (이전 판의 "5만 장 기준 1~2억 원" 은 계산이 맞지 않아 2026-09-18 정정)
- **긴 설명도 명사형으로 끝낸다.** 근거 · 난이도처럼 두 문장이 이어질 때 서술형으로 되돌아가기 쉽다
  (2026-09-18 재지적 — 전역 규칙은 `CLAUDE.md` 문장 규칙 5절).
  - **"원천 데이터"** : 1단계는 현장 · 사내에서 실제 활용에 필요한 데이터를 모으는 단계로 적는다.
- 4단계 제목은 「적용 환경 준비」 → **「서빙 환경 구성」**으로 확정(2026-09-18) — 사내에서 쓰는 말이고
  LLM(사내 서버 서빙) · Vision(현장 장비 탑재)이 한 번에 읽힌다.
- 단계 내용은 `steps.py` 한 곳에만 있다. 본 덱과 첨부 6장이 같은 파일을 읽으므로 **문구는 여기서만 고친다.**

## 구성 (2026-09-18 개정)
- **본 덱** : 결론 밴드 · 각주 · 첨부 안내 줄을 모두 빼고 **6단계만 크게**.
  박스 하나 = 번호 + 아이콘 + 제목 + 부제 한 줄 + 우상단 첨부 개체.
  **6개 박스는 서로 동등하게 그린다** — 강조 박스를 두지 않는다(2026-09-18).
  하단에 **6단계 → 1단계 순환 화살표**(금색)와 「1~6 단계 사이클 반복 — 반복마다 성능 향상 · 불량 감소」를 둔다.
  단순 재투입이 아니라 사이클을 돌며 성능이 올라가는 과정이라는 뜻이다(2026-09-18).
  화살표가 지나갈 좌측 · 하단 여백은 `MX0` · `LOOP_H` 로 확보한다.
- **첨부** : 결론 밴드 · 각주 없이 3열만. 각 열 = 파트명 + 그림 자리 + 핵심 한 줄.

## 그림
| 어디에 | 무엇 | 출처 |
|---|---|---|
| 본 덱 6개 박스 | 단계 아이콘 6종 | `make_icons.py` 가 그린 SVG → `png/step*.png` |
| 첨부 LLM · Vision 칸 | 단계별 3D 일러스트 12장 | 사용자가 `sample/ai-pipeline-6steps-1~6.pptx` 에 넣어 준 그림을 추출 → `img/step{N}_{llm\|vis}.png` |

- 칸마다 **큰 그림 1장**이다(약 3.8"). 그림 자체가 그 단계의 흐름을 담고 있어 별도 흐름 도식을 두지 않는다
  (2026-09-18 — 그 전의 작은 그림 3장 + 화살표 방식은 폐기).
- 그림을 바꾸려면 `img/step{N}_llm.png` · `img/step{N}_vis.png` 를 교체하면 된다. 파일명만 맞추면 코드 수정이 없다.
- **PNG 의 투명 여백은 미리 잘라 둔다.** 여백이 남아 있으면 같은 자리에서 그림이 작아 보인다.
  긴 변 900px 로 줄여 저장한다(약 3.8" × 230dpi).
- 로봇 칸은 글자 없이 점선 빈 상자만 둔다.

## 아이콘 (본 덱)
`make_icons.py` 가 6종을 SVG 로 그려 `svg/` 에 저장하고 rsvg-convert 로 `png/` 에 600×600 PNG 를 낸다.
Codex 를 쓰지 않는다 — 개념 도식 · 선화 계열은 Claude 가 SVG 코드로 그리는 것이 프로젝트 규칙이다.
팔레트는 덱과 같고(네이비 외곽선 · 파랑 · 금색 포인트 1곳), 선 굵기는 `SW` 하나로 6종 공통이다.

```bash
python3 input/ai-pipeline-6steps/make_icons.py   # svg/ · png/ 재생성
```
